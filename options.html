LinkedIn Spider · settings

Every sent connection request can be pushed into celox ops as a Rainmaker lead with status angeschrieben. ops recognises people already in your pipeline by their profile URL and only fills in what is missing — nothing is overwritten, nobody is moved backwards.

Connection

Create the token in ops under Einstellungen → API-Token für LinkedIn Spider. It can only import leads — it cannot read, change or delete anything else. It is stored in this browser profile only.

Behaviour

Off: nothing leaves the browser until you press Sync in the popup.

Pacing

A run scans for the next card about every 1.5 s. Jitter varies that gap (0.9–2.1 s) so the run has no fixed beat. The caps pause a run — it resumes by itself when the window has moved on. Empty or 0 = no cap. LinkedIn's own allowance is about 200 invitations per week.

Forget sync state makes every saved contact pending again. Safe: ops deduplicates by profile URL, so a second push only refreshes what is missing. Use it after switching ops accounts.

Do-not-contact list

ops sends back whom not to ask again: leads closed as lost, dormant or won, people who are customers already, and contacts marked as no longer in their role. Only the profile keys travel — no names. A run skips those cards. The list refreshes with every sync.

Searches

What the picker offers in the page (click the 🕸️ badge on LinkedIn). Each line is one search term; the chosen city is appended to it, exactly as you would type it into LinkedIn's search box.

Sent per combination

Counted per term + city as requests go out — this is the tally, not a view of the contact log, so Clear Log in the popup leaves it alone. A search typed by hand counts too, as long as its city is one of yours.

Updates

Sideloaded extensions do not update themselves. This asks GitHub for the latest release — only when you press the button; Chrome will ask once for access to api.github.com. Afterwards the check repeats at most once a day and the popup footer shows a newer version as a link.
